armGBA speedups on top of third_party/armgba's public commit (bda3645, armGBA-3DS 1.0 on upstream armGBA 2.0), applied in name order to a copy of its src/ in the build folder by `../armgba.mk`; the submodule itself is never touched, and a patch that does not apply stops the build.

The first seventeen patches make exactly the tree of the local armGBA branch opt11/port10, with 0018-0020 the tree of skeptic11/toadflax, and with 0021-0024 that of opt13/tormentil. They are the eighteen that were made against 5e95541 (armGBA-3DS 0.0.6-alpha), brought onto armGBA 2.0, less what armGBA 2.0 now does itself:

- 0001 render-threads: the render workers widen the frames they hand over for the frontend (renderThreadSetWiden), and a line's changed video pages are found eight flags at a time.
- 0002 sound-log: the sound log is published and read with the fewest barriers (`threadLogsLean = false` puts a barrier at every entry again). armGBA 2.0's render log already waits for the line (e9d0ec8), so it is left as it is.
- 0003 timers-and-events: a timer's test of whether an event can run after its instruction leaves the events that aren't a timer's at once.
- 0004 mid-blocks: a place returned to inside a block again and again gets a block of its own (jitSetMidAfter).
- 0005 hblank-dma: H-blank DMA from RAM to video registers moves in one loop, and a video sync that is already done is skipped.
- 0006 compiled-code: events inside blocks spill only the cycle counter and the prefetch base, r0-r4 move with one LDM or STM, and the idle head test is a bitmask.
- 0007 slow-memory: palette and OAM accesses, IE and IME loads and the IE/IF word load run inline in the a32 memory routines.
- 0008 timer-writes: a timer's reload or control write takes effect at once when no event is due, and the timers' replan and quiet-overflow planning do less.
- 0009 io-stores: I/O stores from compiled code have their own slow path, with IE, IF and IME written directly.
- 0010 bios-return: MRS reads the CPSR's flags without the spill, and the BIOS's return from an exception runs without the exact CPU.
- 0011 golden-sun: a compile clears only the compiler state it uses, and the first visits stepped before a block compiles can be set (jitSetCompileAfter).
- 0012 racers: events run after more of the instructions they fall in (jitSetDeferMore).
- 0013 live-map: a state load drops only the compiled blocks over the work RAM words it changes, when there are few.
- 0014 jit-budget: the game and the hidden copy each count their own compiling (jitSetCompileBudget), and the stats count flushes by cause and refused compiles.
- 0015 racers-compile: careful copies and unlinked exits share their stub code, and a careful copy is made even in a frame that has used up its compile time.
- 0016 racers-emulating: `armgba_lazy_carry` works out a flag-setting multiply's carry at the next check's way out when nothing else reads it; `armgba_mid_careful` 2 earns a block a careful copy when returns into its middle keep coming, and 3 also gives a place returned to again and again a block of its own (0 and 1 are armGBA 2.0's own: a return into a block's middle carries on in a copy that is there, 5230ef8).
- 0017 racers-cside: `armgba_cside` is a bit mask. 1: while the render worker draws, the machine's own renderer keeps only DISPCNT, its latch and what a register reads back. 2: the render log's register entries go straight into its ring, and a 32-bit write to two video registers is one entry. 4: a DMA run's writes to video registers are one entry. 16: the interrupt controller's changes that only clear a flag wait in the event list without compiled code stopping for them. Bit 8 is gone: armGBA 2.0's exact CPU steps on its table-driven interpreter, which doesn't decode.
- 0018 timer-write-times: a timer write that 0008 applies at once leaves its event's time where the event would have run, so a state is the same bytes as armGBA 2.0's (the time is kept in states even while the event waits in no list).
- 0019 step-one-flush: a flush asked for while the exact CPU steps an instruction for a careful copy (a write that changes the work RAM's wait states at 0x04000800, or the cartridge's contents changing) waits for the run loop, as every other flush from compiled code does. armGBA 2.0 flushes at once there, and the copy goes on in the blocks it freed (a use-after-free, and a crash on IRQ torture ROMs); a fix for armGBA 2.0 itself, not one of our speedups.
- 0020 mid-blocks-reclaimed: 0004's blocks for returns into another block's middle are counted while they are in the code memory, not since the last flush, so a reclaimed slot (armGBA 2.0, c26cad9) lets as many more be compiled. Without it every scene measured reached the cap within ten minutes (13 MiB of code memory) and stepped each such return from then on.
- 0021 reclaim-lists: a reclaimed slot's blocks that had code in other slots (careful copies and the blocks they copy) come off those slots' lists in one pass over each list, and the lookup's scan for entries into the slot tests one range (Bistort's, from opt12/bistort).
- 0022 slot-list-places: a new block's place in its slot's lists is found by halves when it isn't at the end. A stretch laid out in another's room for bodies puts its cold code below code already in the slot, and the scan from the end read a block per step (about 60 of a compile's 220 data cache misses in Final Fantasy VI, in the a32 sim; with the scan, Baldur's Gate's compiles at a room change took 2-2.7 times as long on a New 2DS XL).
- 0023 reclaim-flushes: a reclaim's unlinked jumps reach the instruction cache all at once. While the slot's blocks are taken out, `jitHostFlushBatch` (`../../ctr/jitmem.c`) has the 3DS host only note each change of code, then clean the whole data cache and invalidate the whole instruction cache in one kernel call, where each jump had a kernel call of its own (thousands a reclaim); on hardware only, as Azahar flushes each change as before. The list of cartridge blocks and the other slots' lists are passed over with a bit for each block going away, kept on the stack, so a block that isn't one isn't read (a cache miss each: 3-4 ms of a reclaim).
- 0024 no-lookup-scan: a reclaim no longer scans the whole lookup (768 KiB) for entries into the slot. An entry is only ever a valid block's head or a careful copy's entry, and taking the slot's blocks out has emptied those; the scan took 2 ms of each reclaim and never found one, on the console or in the sim with a check that stopped if it did (every master, at 4 and 16 MiB of code memory).

0021-0024 took Final Fantasy VI's reclaims (a full code memory making room) from 13-25 ms to 6-11 ms on a New 2DS XL. None of them changes the code compiled or any allocation (the two marks 0021 adds to a block fit in its padding: 176 bytes before and after), nor what decides which blocks compile, but for `armgba_compile_budget` (0014), which counts time: a cheaper compile or reclaim reaches it later in a frame, as a faster console would (Baldur's Gate then compiles a few dozen blocks of a new room at once that it would have put off, and holds 10-20 KiB more of the heap from then on).

What armGBA 2.0 does itself, so the patch went: 0006 irq-events (IE, IF and IME writes take effect at once: 216aa64), the IE writes that flip the H-blank bit (old 0010: 78ff173 and 216aa64), MSR without the exact CPU and an IRQ taken where compiled code is (old 0011: 9cdbe86, 5230ef8), and the render log's barriers (old 0002: e9d0ec8). Old 0015's arena for blocks' records is gone too: a full code memory now reclaims a slot instead of flushing (c26cad9), so the records are freed slot by slot. Two parts no longer paid on 2.0, measured in a32 instructions under qemu, so they went: old 0003's shortcut for the interrupt pipeline's events (after 216aa64 few of them are left, and the test cost more than it saved) and old 0004's halfword I/O store (2.0's busWrite is as quick).

The knobs the patches add are off as built (armGBA 2.0's own behaviour) but for `armgba_mid_after` (16), `armgba_defer` (on) and `armgba_lean_logs` (on); the 3DS's gba-ds.cfg defaults turn on the rest: `armgba_lazy_carry = 1`, `armgba_mid_careful = 3` and `armgba_cside = 31` (bit 8 does nothing now). 0 for any of them gives 2.0's way, for a console's A/B. 0018-0024 have no knob. The hidden copy's code memory (`armgba_copy_code_mib`, `auto` by default: 4 MiB beside a 32 MiB ROM, else 8) is GBA DS's own `../../ctr/jitmem.c`, not a patch.

They can be folded into ratherDashing/armGBA's 3ds-release; after that, move the submodule pointer to it and delete this folder and the copying in `../armgba.mk`.
